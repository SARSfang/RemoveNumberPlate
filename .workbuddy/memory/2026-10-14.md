### 发布前发现并修复的关键缺陷

原 CI 发布流程**不包含高清组件**，与 RELEASE.md v1.2.0 的说明直接矛盾——若照原样发布，用户下载的安装包会缺少"高分辨率"选项。

修复内容：
- `release.yml` 显式下载并校验 Big-LaMa 权重（该权重在 `models/manifest.json` 中 `enabled: false`，`build_models` 会跳过）
- `release.yml` 新建独立 `.venv-hd`（CPU-only torch），保持 PyTorch 不进入标准运行时
- `build_release.ps1` 新增 `-SkipHdRuntime` 开关，把 hd-runtime / big-lama.pt / 高清许可合并进 PyInstaller 输出目录（`installer.iss` 已用 `recursesubdirs` 递归打包该目录）
- 产物体积从 158 MB 涨到约 1 GB，原 `lzma2/ultra64` + `SolidCompression=yes` 会超时，改为 `lzma2/max` + `SolidCompression=no`
- CI 超时 60 → 120 分钟

### 踩坑记录

1. **提交信息里出现 `PowerShell` 字样会被 Bash 工具的安全策略拦截**（误判为"从 Bash 调用 PowerShell"）。改用 `git commit -F <文件>`。
2. **版本约束必须加引号**：`pip install pyinstaller>=6.16,<7` 在 pwsh 中把 `>` 当重定向符解析。写成 `"pyinstaller>=6.16,<7"`。
3. **`build_release.ps1` 原有"dist 下有且仅有一个发布目录"的检查**会因 `hd-component` / `hd-preview-final` 目录而失败，必须加入排除列表。
4. 校验 GitHub Actions 内嵌脚本块的方法：先用 PyYAML 抽出 `run` 字段存成 `.ps1`，再用 PowerShell 的 `[Parser]::ParseFile` 校验。用 PS 解析器直接读 YAML 会产生大量假错误。

325 单元测试 + 33 前端测试通过，ruff / mypy 无问题。顺带修掉 HD 脚本里 3 个既有 mypy 错误（`RUNTIME_DISTRIBUTIONS` 定长元组赋值、`build_plate_mask` 形状类型、`Detection.as_dict` 不存在——后者用 `dataclasses.asdict` 替代）。
