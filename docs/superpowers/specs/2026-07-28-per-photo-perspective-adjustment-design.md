# 每张照片四点透视调整设计规格

**日期：** 2026-07-28  
**状态：** 已完成设计讨论，等待用户审阅  
**目标版本：** `v0.2.0-rc.6`  
**产品：** 消除车牌 Windows 桌面版

## 1. 背景与目标

真实摄影样片验证中，四张照片只有一张结果令人满意，且四张均未触发风险复核。现有流程只有 `REVIEW_REQUIRED` 任务可进入复核；已完成照片没有调整入口。与此同时，车牌检测器内部得到的带角度四点框在领域模型和数据库中被压成水平矩形，遮罩随后又按检测框高度向左右约各扩一个高度、上下各扩 40%，导致透视车牌周围的大块车身被不必要地消除。

本轮目标是：

1. 每张非处理中照片均可按需进入调整，不依赖自动风险判断。
2. 端到端保留车牌四点透视几何，并以可编辑四边形生成遮罩。
3. 调整后先生成本地临时预览，满意后才保存新结果。
4. 保持原图、旧结果、旧任务数据库和离线隐私不变。
5. 日常迭代使用固定免安装测试目录，不再反复安装和卸载。

不引入新模型、训练、云服务、账号、在线接口、Qt 或 Electron。

## 2. 已批准的交互

### 2.1 调整入口

采用“主预览固定入口”：

- 当前选中照片的主预览顶部显示“调整区域”。
- 用户先通过胶片带选择照片，再进入调整。
- 已完成、未发现车牌、待复核、失败和已取消任务均可进入。
- 排队、检测、修复或写入中的任务暂时禁用入口，并显示“处理完成后可调整”。
- 原图丢失时禁用入口并显示“原图已移动或删除”。
- 不在每个缩略图上放置按钮，也不要求先打开详情抽屉。

### 2.2 编辑器

复用现有待复核编辑器的全尺寸画布和视觉语言，但将其扩展为通用照片调整器：

- 编辑始终基于原图，不对旧修复结果二次修复。
- 自动检测以四点透视框显示；四角可独立拖动，框内拖动可整体移动。
- 支持新增四点框、选择多个车牌框、删除框、恢复自动框。
- 保留画笔补充、橡皮擦、撤销、重做、缩放、平移和遮罩透明度。
- 默认边缘余量为四边形短边的 8%；滑杆范围为 -15% 至 +35%，步进 1%，作用于当前选中框。
- 无自动检测时打开空编辑器，引导用户新增四点框。
- 离开前若存在未提交编辑，继续显示放弃确认。

### 2.3 临时预览与保存

采用三步流程：

1. 调整区域。
2. 生成临时预览。
3. 保存新结果。

生成临时预览时：

- 本机 LaMa 只重修当前照片。
- 临时结果保存在应用缓存，不进入照片输出文件夹。
- 新预览替换同一调整会话的旧预览。
- 用户可在“原图＋遮罩”和“临时结果”之间分栏切换，不并排显示。
- 生成失败时保留全部编辑，允许重试。

保存时：

- 仅保存当前最新且与编辑版本一致的临时预览。
- 使用现有安全命名生成 `_clean_2`、`_clean_3` 等文件。
- 原图和旧结果永不覆盖。
- 保存后更新批处理主预览、任务历史及任务的最新输出引用。
- 旧遮罩修订和旧结果继续保留，方便回看与回退。

取消、关闭应用或会话超时会清除临时缓存，不修改正式结果。

## 3. 几何与持久化

### 3.1 领域模型

`Detection` 新增四点多边形；新检测结果必须填写，只有兼容旧记录时允许缺省：

```text
polygon = ((x1, y1), (x2, y2), (x3, y3), (x4, y4))
```

约束：

- 顺序固定为左上、右上、右下、左下。
- 四点位于方向归一化后的原图像素坐标中。
- 多边形不得自交，面积必须大于零。
- `BoundingBox` 继续保留，并由四点外接矩形得到，用于风险门、旧接口和兼容测试。
- 旧检测记录缺少四点时，以原外接矩形四角作为兼容多边形。

检测器解码时必须保留当前已经计算出的 `expanded_box` 四点，不得再次压成水平框后作为遮罩来源。

### 3.2 数据库迁移

任务数据库从模式版本 3 升级到版本 4，在 `detections` 中增加四点 JSON 字段。迁移要求：

- 旧数据库原地兼容升级。
- 旧行允许四点字段为空，读取时使用矩形四角。
- 不重写、删除或重新推理旧任务。
- 数据库完整性检查和损坏隔离逻辑保持不变。

遮罩修订继续使用 JSON，但新增明确命令：

- `set_detection_polygon`：修改某个自动框的四点。
- `add_polygon`：新增手动四点框。
- `remove_detection`：删除某个自动框。
- `brush_add` / `brush_erase`：补充或擦除遮罩。
- `set_margin`：保存选中四点框的边缘余量。

后端对命令数量、点数、数值、坐标范围、自交和最小面积执行独立校验，不信任前端。

### 3.3 遮罩生成

- 自动遮罩使用 `cv2.fillPoly` 填充透视四边形。
- 边缘余量沿多边形外轮廓偏移，默认值为短边的 8%。
- 不再叠加原有左右约一个框高、上下 40% 的水平矩形扩张。
- 多个车牌框取并集；橡皮擦命令最后应用。
- 所有结果裁剪到原图边界。

## 4. 本地调整接口与数据流

新增受任务 ID 限制的桥接能力，前端不得传入文件路径：

```text
get_adjustment_job(job_id)
preview_adjustment(job_id, revision, commands)
save_adjustment(job_id, preview_token)
cancel_adjustment(job_id)
```

`get_adjustment_job` 返回原图预览、尺寸、四点检测、最新遮罩修订、任务状态和入口可用性。

`preview_adjustment`：

- 校验任务、原图、修订号和全部命令。
- 批处理或另一调整任务占用模型时返回结构化忙碌状态。
- 异步生成全分辨率临时结果和受限尺寸预览。
- 返回与任务、编辑修订和临时文件绑定的不透明 `preview_token`。
- 同一时间只允许一个调整推理；同一会话只保留最新临时结果。
- token 使用不可预测随机值，30 分钟后过期；取消、重新预览、继续编辑或应用退出都会提前失效。

`save_adjustment`：

- 拒绝未知、过期、任务不匹配或编辑修订不一致的 token。
- 将已经验证的临时结果原子写入版本化正式路径，不再次推理。
- 记录遮罩修订并更新任务输出；不得删除检测四点。
- 将任务状态设为 `COMPLETED` 并清除旧风险；失败、取消、无车牌和待复核任务均遵循同一规则。
- 成功后发出结果更新、历史更新和临时缓存清理事件。

`cancel_adjustment` 清理当前会话缓存但不改变任务状态或正式输出。

临时文件位于应用缓存目录，启动时清理遗留项；诊断包不包含照片、临时预览或遮罩内容。

## 5. 状态与失败处理

- 打开编辑器不会把正常完成任务强制改为 `REVIEW_REQUIRED`。
- 待复核任务仍保留风险语义，但与普通任务共享同一编辑器。
- 预览期间显示明确进度并禁用会改变遮罩的控件；取消返回仍可用。
- 原图移动、预览 token 过期、磁盘空间不足、模型失败和写入失败均返回可恢复错误。
- 预览失败保留编辑；保存失败保留已生成的临时预览，可再次保存。
- 临时预览生成后继续编辑会立刻使 token 失效，必须重新生成预览。
- 应用崩溃或退出不会留下正式半文件；现有原子写入验证继续使用。

## 6. 固定免安装测试版

新增仅供高频验收的预览构建流程：

- 输出到稳定路径 `dist\preview\消除车牌\消除车牌.exe`。
- 提供固定的“打开测试版”启动入口；用户每轮关闭旧进程后重新双击同一入口。
- 构建只执行模型校验、自动测试、PyInstaller 和桌面 smoke，不调用 Inno Setup，不注册卸载信息。
- 测试版沿用正式应用的本地设置和任务历史；覆盖程序目录不会删除用户数据。
- 正式安装器只在候选发布时构建，并继续执行静默安装、启动和卸载验收。

## 7. 测试与验收

### 自动测试

- 检测器保留四点顺序、缩放映射和外接矩形。
- 多边形遮罩、8% 外扩、边界裁剪、多框并集及旧矩形回退。
- 自交、越界、零面积、超量命令和非数值输入被拒绝。
- 数据库旧版本迁移后可读取、继续处理且不丢历史。
- 每种非处理中任务状态均可打开调整；处理中和缺失原图不可打开。
- 临时预览不增加正式输出文件；保存只增加一个版本。
- token 的任务绑定、修订绑定、过期、取消和重放保护。
- 手动保存不清除原检测四点，第二次调整能恢复最新修订。
- 前端四角拖动、整体移动、新增/删除框、画笔、橡皮擦、撤销/重做和未保存离开保护。
- 主预览“调整区域”在 1040×680、常用宽屏和 200% 缩放下可见。
- 免安装测试构建 smoke 通过，正式安装器回归保持通过。

### 摄影师验收

使用本轮四张实拍作为首个回归集：

1. 四张均能从主预览进入调整。
2. 自动框保持车牌透视，不退化为水平大矩形。
3. 默认遮罩明显减少对保险杠、格栅和车身纹理的覆盖。
4. 每张可在四角调整后生成临时预览。
5. 生成临时预览前后，输出文件夹文件数不变。
6. 保存后只新增一个带序号结果，原图和旧结果未修改。

成功标准不是四张自动结果全部无需人工，而是四张都有快速、可预测、可回退的调整路径，并且透视遮罩显著降低不必要覆盖。

## 8. 实施边界

- 保持 WebView2、原生 HTML/CSS/JavaScript、Python 和 ONNX Runtime。
- 不更换检测模型或修复模型，不要求训练。
- 不新增云服务、账户、付费 API、遥测或网络权限。
- 不将本轮扩展为完整照片管理、批量调色、RAW 支持或自动更新器。
- 正式实现前以本规格为唯一功能基线；视觉微调继承现有 RC5 设计系统。
