# 桌面版预览优先工作台设计规格

**日期：** 2026-07-28  
**状态：** 已批准，等待实施计划  
**目标版本：** `v0.2.0-rc.5`  
**产品：** 消除车牌 Windows 桌面版  
**视觉基准：** [方案 2：底部胶片带 + 大幅单图预览](../../design/desktop-preview-workspace-option-2.png)

## 1. 背景

当前桌面版已经具备批处理、风险复核、任务历史、设置、诊断和本地恢复能力，处理管线也已稳定。现有前端的主要问题不再是功能缺失，而是：

- 批处理页以拖入区、统计卡和任务表格为中心，照片本身不够突出。
- 大量空间用于网页式说明和卡片，任务运行后的高频操作反而较分散。
- 批处理、复核、历史和设置虽然功能完整，但视觉语言与信息密度不够统一。
- 单一 `app/web/app.js` 同时承担桥接、状态、批处理、复核画布、历史和设置逻辑，继续扩展会降低可靠性。

本轮将桌面版升级为以照片为中心的专业摄影工作台，同时保留 WebView2、原生 HTML/CSS/JavaScript 和现有 Python 处理核心，不引入 Qt、React 或在线依赖。

## 2. 目标

### 2.1 用户目标

汽车摄影师能够：

1. 拖入一批 JPEG、PNG 或 TIFF 照片。
2. 在 AI 后台处理时直接查看当前照片和处理结果。
3. 快速浏览整批任务，并明确区分当前处理项与当前预览项。
4. 固定查看某张照片而不被后台进度打断。
5. 对风险照片进入现有人工复核流程。
6. 在最小窗口与高缩放下仍能完成核心操作。

### 2.2 产品目标

- 形成高端、克制、摄影优先的视觉语言。
- 提高批处理中的信息可见性和操作效率。
- 不增加云服务、账号、训练、网络或遥测。
- 不降低现有处理效果、恢复能力、隐私和安装包可靠性。
- 保持启动快、内存受控、无前端运行时框架。

## 3. 非目标

本轮不包括：

- 网页版或云端推理。
- RAW/CR3/NEF/ARW 支持。
- 并排显示原图与结果。
- Lightroom 式完整调色或文件管理。
- 在批处理页直接编辑遮罩。
- 训练或微调模型。
- 更换检测器、修复模型或当前扩边策略。
- 新增账号、付费、同步或在线字体。
- 迁移到 Qt、Electron、React 或 Tailwind。

## 4. 设计方向

### 4.1 选定方向

采用“底部胶片带 + 大幅单图预览”：

- 顶部保留轻量主导航。
- 导航下方是紧凑批次命令栏。
- 中央是唯一的主照片预览。
- 右侧是可折叠照片信息栏。
- 底部是横向胶片带。

视觉稿是层级和质感参考，不是逐像素功能清单。视觉稿中的 CR3、额外输出质量编辑和模型版本入口不纳入本轮。

### 4.2 被否决的方向

- **三列常驻队列/画布/检查器：** 信息完整，但在 1040px 最小宽度下挤压照片。
- **左侧纯文本列表：** 密度高，但不符合摄影师通过缩略图识别照片的工作方式。
- **保留当前仪表盘，仅美化颜色：** 无法解决照片不突出和操作路径分散的问题。

## 5. 信息架构

主导航维持四个一级工作区：

1. 批处理
2. 待复核
3. 任务历史
4. 设置

不新增一级导航。待复核数量继续以低干扰徽标显示。

## 6. 批处理工作区

### 6.1 空批次

空批次时，中央照片画布同时承担拖放入口：

- 主文案：“拖入照片或文件夹”
- 支持格式：“JPEG、PNG、TIFF，可递归扫描文件夹”
- 主操作：“选择照片”
- 次操作：“选择文件夹”
- 本地隐私提示：“完全离线，原片不会上传”

此时不显示五张统计卡，也不显示空任务表。

### 6.2 批次命令栏

任务存在后显示：

- 固定标题“本次处理”与图片总数
- 图片总数
- 整体完成数与百分比
- 整体进度条
- 暂停/继续
- 取消剩余任务
- 添加照片
- 进入待复核

“进入待复核”是当前页面唯一允许使用实心主色的操作；无待复核项时使用真实禁用语义。

当前批次运行或暂停期间，“添加照片”保持可见但禁用，并提示“当前批次结束后可添加”。本轮不扩展 `BatchService` 以动态插入任务。批次结束或取消后恢复可用。

“取消剩余任务”必须打开确认对话框，说明：

- 当前正在推理的图片会完成还是立即停止。
- 尚未开始的图片将标记为已取消。
- 已完成输出不会删除。

### 6.3 主照片画布

照片画布是页面视觉中心：

- 只有一个预览，不并排比较。
- 顶部使用“原图 / 处理结果”标签。
- 默认以适应窗口显示。
- 支持适应窗口、1:1、放大、缩小和拖动画布。
- 画布背景使用中性近黑，避免影响照片判断。
- 图片切换使用短淡入，不缩放、不弹跳。
- 预览请求发出后立即保留固定画布；300ms 内未完成时显示骨架状态。

原图标签在任务创建后可用。处理结果标签仅在输出已验证且文件仍存在时可用。

选择新照片时优先保持用户最近选择的标签；若该照片没有可用结果，则回退到原图并解释原因。处于“跟随处理中”模式时，任务成功完成后自动切换到处理结果；待复核、未发现车牌或失败则保持原图。

### 6.4 预览跟随状态

预览有两个互斥模式：

#### 跟随处理中

- 批次开始后的默认模式。
- `item_started` 到达时选择新的当前处理项。
- 当前处理项结束后保持显示其结果，直到下一项开始。

#### 已固定

- 用户点击任意胶片项时进入。
- 后台任务继续运行，但不改变当前预览。
- 显示“已固定”状态和“恢复跟随”操作。
- 恢复后立即选择当前处理项；若批次已结束，则选择最后完成项。

“当前处理”和“当前预览”分别表达：

- 当前处理：进度图标、状态文字或细进度。
- 当前预览：选中边框和焦点状态。

两者不得只依赖颜色。

### 6.5 底部胶片带

每个胶片项包含：

- 固定比例缩略图
- 短文件名
- 排队、处理中、完成、待复核、未发现车牌、失败或取消状态
- 当前处理与当前预览标记

交互规则：

- 单击选择并固定预览。
- 左右方向键移动选择。
- Home/End 选择首项或末项。
- 当前项自动滚动到可见范围。
- 鼠标滚轮在胶片带上转换为横向滚动。
- 长文件名省略，完整名称在提示与右侧信息栏显示。

性能规则：

- 先渲染固定尺寸占位，避免任务发现后布局跳动。
- 缩略图按可见区域和前后缓冲区懒加载。
- 任务数达到 40 项时启用窗口化列表，DOM 中只保留可见区域和前后缓冲项。
- 单个状态事件只更新对应项目。
- 前端缩略图缓存最多 64 项，主预览缓存最多 6 项；移出缓存时释放引用。

### 6.6 右侧信息栏

默认显示当前预览照片：

- 文件名
- 像素尺寸
- 当前状态
- 处理耗时
- 风险原因
- 输出文件名
- 打开输出目录
- 进入复核、手动标记或重新处理等上下文操作

不显示可在设置页完成的模型或输出质量配置。

窗口内容宽度小于 1180px 时，信息栏折叠为从右侧打开的详情抽屉；主画布和胶片带保持可用。

## 7. 批处理数据流

### 7.1 任务发现

当前后端只在某一项开始时发送 `item_started`。胶片带需要在处理第一张之前获取完整有序任务清单，因此增加事件：

```json
{
  "name": "batch_items_ready",
  "payload": {
    "total": 3,
    "items": [
      {
        "id": "job-id",
        "name": "car-001.jpg",
        "index": 1,
        "status": "queued"
      }
    ]
  }
}
```

事件在图片发现、磁盘预检和任务记录创建完成后发送，并早于模型会话首次加载。前端不需要完整来源路径即可渲染胶片带。若后续模型初始化失败，后端将本批仍在排队的任务标记为失败，并发送可恢复的结构化错误，避免留下永久排队状态。

### 7.2 预览接口

增加允许列表接口：

```text
get_job_thumbnail(job_id)
get_job_preview(job_id, variant)
```

`variant` 只接受：

- `original`
- `result`

后端必须：

1. 仅通过任务数据库查找源文件或输出文件。
2. 拒绝前端直接传入任意文件路径。
3. 进行 EXIF 方向归一化。
4. 缩略图限制在 320×220 的边界内，JPEG 质量为 72。
5. 主预览限制在 1800×1200 的边界内，JPEG 质量为 88。
6. 返回 JPEG 数据 URL、原始像素尺寸和可用状态。
7. 在结果不存在、任务未完成或文件被移动时返回结构化不可用原因。
8. 不写入永久缩略图或缓存文件。

响应必须遵循：

```json
{
  "available": true,
  "image": "data:image/jpeg;base64,...",
  "width": 6000,
  "height": 4000,
  "variant": "result",
  "message": ""
}
```

### 7.3 结果操作

新增基于任务 ID 的输出操作：

```text
open_job_output(job_id)
```

它替代新界面向 Python 传回文件路径的做法。后端通过任务数据库解析输出，并继续验证目标是应用的输出目录。

### 7.4 前端状态

批处理状态至少包含：

- 有序任务数组
- `activeProcessingId`
- `selectedPreviewId`
- `previewMode`: `following | pinned`
- `previewVariant`: `original | result`
- 运行、暂停、取消和完成状态
- 每项状态、耗时、输出可用性与风险
- 有上限的缩略图和主预览缓存

状态转换应集中管理，不允许各组件直接拼接互相矛盾的 DOM 状态。

## 8. 待复核工作区

保持当前复核能力，不改变人工遮罩含义：

- 左侧：紧凑待复核列表。
- 中央：单图画布。
- 顶部：分组工具栏。
- 底部：文件、风险和导航/确认操作。

工具分组：

1. 矩形、添加画笔、擦除画笔、删除自动框
2. 撤销、重做、恢复自动框
3. 适应、1:1、缩放、遮罩显示和透明度
4. 当前工具参数

笔刷大小只在画笔工具激活时显示。

确认重修时：

- 禁用会修改当前遮罩的操作。
- 显示明确进度。
- 成功后进入下一张。
- 失败时保留命令历史和当前选择。

“确认并重修”是唯一主按钮；上一张、下一张为中性操作；跳过降低强调并说明不会修改原片。

## 9. 任务历史

移除现有顶部两张大说明卡。历史页以任务记录为主：

- 顶部：总数、状态筛选、文件名搜索、刷新、本机隐私提示。
- 主体：紧凑任务列表。
- 选中任务时可复用预览与信息详情。

状态相关操作：

- 完成：打开输出。
- 待复核：进入复核。
- 未发现车牌：手动标记。
- 失败或取消：重新处理。
- 原片已移动：显示不可恢复原因并禁用无效操作。

本轮不增加删除、移动或批量重命名。

## 10. 设置

设置重组为：

### 处理

- 处理预设
- 对速度、检出率和修复上下文的简短解释

### 性能

- 当前计算设备
- 模型准备状态
- 本地离线运行状态

### 数据与支持

- 本机任务记录说明
- 导出诊断包
- 使用指南
- 故障排除
- 隐私说明
- 可折叠运行环境详情

WebView2 版本、模型哈希和运行时等只读技术信息默认折叠。设置保存使用短暂内联确认或 Toast，不使用普通成功弹窗。

## 11. 视觉系统

### 11.1 设计哲学

采用“Geometric Silence / 几何静默”：

- 照片比装饰更重要。
- 通过精确网格、间距和明暗层次组织信息。
- 文本简短、中文统一。
- 色彩只承担状态和选择含义。
- 高端感来自克制和精度，不来自玻璃拟态或大量发光。

### 11.2 三层设计变量

CSS 变量分为：

1. 原始值：颜色阶、4px 间距阶、字号、圆角、时长。
2. 语义值：画布、表面、文字、主色、成功、警告、危险、焦点。
3. 组件值：按钮、标签、胶片项、画布、信息栏、对话框、Toast。

组件不得散落重复原始颜色值。

### 11.3 色彩

- 画布：近黑蓝灰，不使用纯黑。
- 表面：最多两级常驻深色表面。
- 照片背景：中性近黑。
- 主色：冷静摄影蓝，只用于选择、进度、焦点和主要操作。
- 成功：低饱和青绿。
- 待复核：暖琥珀。
- 失败：克制珊瑚红。
- 分隔：低对比半透明边线。

### 11.4 字体

- 中文：Microsoft YaHei UI。
- 数字与英文：Segoe UI。
- 正文基准：14px。
- 文件名和关键状态：14–15px。
- 分区标题：16–18px。
- 页面或批次标题：18–22px。
- 不再使用英文 eyebrow 装饰标题。
- 时间、数量和进度使用 tabular figures。

### 11.5 间距与形状

- 4px 基础网格。
- 常用间距：8、12、16、24px。
- 工具按钮视觉高度 32px，但图标按钮保持足够可点击区域。
- 主要按钮高度 40px。
- 圆角主要为 6、8、10px。
- 优先使用间距和分隔线，不使用卡片套卡片。
- 阴影仅用于对话框、抽屉和 Toast。

### 11.6 图标

- 使用本地打包的 Lucide 图标子集。
- 统一线性风格、尺寸和描边。
- 不使用 emoji、CSS 拼图标或来源混杂的图标。
- 图标按钮提供中文 `aria-label` 和可见提示。

### 11.7 动效

- 常规交互 120–180ms。
- 只动画 `opacity`、`transform`、颜色和必要进度。
- 不用动效改变布局尺寸。
- 不使用弹跳、视差或装饰性循环动画。
- 支持 `prefers-reduced-motion`。

## 12. 通用交互与无障碍

- 所有按钮使用语义 HTML。
- 标签采用正确的 `tablist/tab/tabpanel` 关系和方向键行为。
- 胶片带采用可键盘选择的列表模式。
- 状态更新通过 `aria-live="polite"` 播报。
- 错误通过文字、图标和颜色共同表达。
- 正文对比度目标至少 4.5:1；UI 图形和焦点至少 3:1。
- 焦点轮廓不得移除。
- 对话框锁定焦点，Esc 关闭，关闭后焦点回到触发按钮。
- Toast 不抢焦点，3–5 秒自动消失。
- 禁用和加载状态使用真实属性与 ARIA 状态。
- 200% 界面缩放时不得遮挡添加照片、暂停、取消、结果切换和进入复核。

快捷键：

- `Ctrl+O`：添加照片。
- `← / →`：在胶片带中浏览。
- `Home / End`：首项/末项。
- `1 / 2`：原图/处理结果。
- `F`：恢复自动跟随。

除 `Ctrl+O` 外，快捷键只在批处理页且焦点不位于输入框、选择框、对话框或复核画布时生效。所有快捷键必须有可见操作替代，不覆盖系统级快捷键。复核画布已有快捷键继续有效。

## 13. 错误与恢复

### 13.1 预览错误

预览失败不影响批处理：

- 保留胶片项和状态。
- 画布显示“无法载入预览”。
- 提供重试。
- 右侧仍显示任务信息。

### 13.2 任务状态

- 待复核：显示风险原因和进入复核。
- 未发现车牌：提供手动标记。
- 失败：说明简明原因并提供重新处理。
- 原片移动：说明原片不可用并禁用依赖原片的操作。
- 输出移动：结果标签不可用，但不破坏历史记录。

### 13.3 数据恢复

现有任务数据库恢复、设置恢复和中断任务恢复逻辑必须保持。恢复后的任务历史应能继续显示；找不到照片时显示明确状态。

## 14. 前端代码边界

保持无框架和无打包器。为避免 WebView2 本地文件模块兼容风险，采用多个 `defer` 经典脚本和单一 `window.PlateApp` 命名空间。本轮不使用 ES Modules。

脚本按以下职责拆分：

- `core/state.js`：状态与纯转换。
- `core/bridge.js`：Python API 和后端事件。
- `components/dialog.js`：确认对话框。
- `components/toast.js`：状态播报。
- `batch/workspace.js`：批次命令栏。
- `batch/preview.js`：预览、缩放和跟随。
- `batch/filmstrip.js`：窗口化胶片带。
- `review/editor.js`：现有复核画布。
- `history/history.js`：历史筛选、搜索和操作。
- `settings/settings.js`：设置与运行环境详情。
- `app.js`：启动和页面导航。

## 15. 测试与验收

## 17. 成功标准

本设计完成的判定不是“页面看起来更暗”，而是：

- 打开软件后，用户第一眼看到照片与批次状态，而不是统计卡。
- 处理期间可以检查任意照片，又不会干扰后台运行。
- 用户能明确知道预览是否正在跟随。
- 风险与错误都有可执行的恢复路径。
- 四个工作区共享同一套精确、克制的视觉系统。
- 100 张级批次、最小窗口、键盘和恢复场景均通过验证。
- 软件仍然离线、轻量、无需训练且不产生额外服务费用。
