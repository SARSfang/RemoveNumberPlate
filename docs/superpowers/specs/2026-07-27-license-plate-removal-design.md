# 全自动车牌消除软件设计规格

日期：2026-07-27  
状态：用户已于 2026-07-27 确认通过
目标平台：Windows 10/11，NVIDIA 独立显卡（6 GB 及以上显存）

## 1. 产品目标

为汽车摄影师提供一款完全离线的桌面软件。用户拖入一批已导出的照片后，软件自动检测并消除所有可见中国车牌，正常图片持续输出，只有低置信或高风险图片进入待复核列表。

产品优先级依次为：

1. 不覆盖或损坏原片；
2. 商拍可交付的视觉质量；
3. 批量流程尽量无人值守；
4. 漏检和误检可快速人工补救；
5. 依赖、安装包和运行资源保持轻量；
6. 模型、数据和照片全程留在本机。

## 2. 已确认范围

### 2.1 第一版包含

- Windows 桌面应用；
- 拖入多张图片或整个文件夹；
- JPEG、PNG、TIFF 输入；
- 中国大陆常见蓝色、绿色和黄色车牌；
- 单图多个车牌；
- 高置信图片自动处理；
- 异常收件箱；
- 矩形框、画笔、橡皮擦、撤销和重做；
- 暂停、继续、取消剩余任务；
- 崩溃或关机后的任务恢复；
- EXIF、ICC、DPI 和拍摄时间保留；
- 完全离线推理；
- NVIDIA GPU 加速；
- 原目录旁安全输出。

### 2.2 第一版不包含

- RAW、DNG、CR2、CR3、NEF、ARW；
- 视频；
- 云端修复；
- OCR 或车牌号码存储；
- 面向用户的模型训练和数据标注；
- Photoshop 级套索、内容感知参数和图层系统；
- macOS；
- 内置扩散模型或其他数 GB 的高级生成式修复模型。

## 3. 核心用户流程

1. 用户拖入照片或文件夹。
2. 软件递归扫描支持的图片，去重后建立持久任务清单。
3. 软件读取图片方向和元数据，生成界面预览。
4. 内置预训练模型检测车牌；大图使用重叠分块检测并合并重复框。
5. 高置信、低风险检测直接进入修复队列。
6. 低置信、小目标、贴边、异常大框或其他高风险结果进入“待复核”。
7. 未发现车牌的图片标记为“未发现车牌”并跳过，不阻塞任务。
8. 正常图片继续输出，异常图片不阻塞整个批次。
9. 用户可切换到“待复核”标签，修改检测框或掩码并单独重修。
10. 结果写入原图所在目录的 `车牌已消除/` 子目录。

输出命名示例：

```text
输入：D:\客户A\IMG_4821.jpg
输出：D:\客户A\车牌已消除\IMG_4821_clean.jpg
```

若输出文件已存在，软件按 `_clean_2`、`_clean_3` 顺序生成新名称，不覆盖旧结果。

## 4. 技术路线

### 4.1 车牌检测

第一版直接内置 PaddleDetection PP-Vehicle 官方预训练车牌检测模型，不要求用户训练或标注数据。官方资料显示车牌检测模型约 3.9 MB，并支持本地部署和 TensorRT 加速。

选择理由：

- 开箱即用，用户不承担训练成本；
- PaddleDetection 项目采用 Apache-2.0；
- 模型体积小；
- 面向中国车牌场景；
- 可与训练框架解耦，部署层可选择 Paddle Inference、TensorRT 或经过验证的 ONNX 路径。

限制：

- 官方模型主要面向交通场景，不能未经实拍验证就宣称适用于所有汽车商拍；
- 模型权重、下载地址、校验值和再分发条款必须在发布前单独归档；
- 如果模型格式转换造成精度下降，优先使用官方部署运行时，而不是强制 ONNX。

### 4.2 图像修复

第一版使用 LaMa 作为默认修复器。LaMa 官方实现采用 Apache-2.0，适合处理较大掩码和重复纹理。部署优先使用经过数值对齐验证的 ONNX/TensorRT 推理，不把完整 PyTorch 训练环境打入发布包。

不采用原方案中的 `simple-lama-inpainting + torch` 作为最终发布依赖，原因是发布包体积、CUDA 依赖和版本组合更重。它仍可用于开发阶段建立基准，但不进入正式运行时。

### 4.3 不采用 Ultralytics YOLO 作为默认方案

Ultralytics 官方许可页面说明，其代码和模型用于闭源商业软件通常需要 Enterprise License；AGPL 路线则带来完整项目开源义务。第一版不将此授权成本和不确定性引入产品。

## 5. 系统架构

各组件通过稳定接口连接，界面不直接依赖具体模型。

### 5.1 Image I/O

职责：

- 读取 JPEG、PNG、TIFF；
- 应用 EXIF Orientation 后向模型提供视觉方向正确的像素；
- 保存 EXIF、ICC、DPI 和拍摄时间；
- 提供低分辨率预览；
- 临时文件验证与原子化写出。

### 5.2 Detector

输入：方向已校正的 RGB 图像。  
输出：车牌候选框、置信度和检测来源分块。

职责：

- 全图或重叠分块检测；
- 坐标还原；
- 非极大值抑制和重复框合并；
- 不执行修复或文件写入。

### 5.3 Risk Gate

输入：检测结果和图片几何信息。  
输出：自动处理、待复核或未发现车牌三种决策。

高风险条件包括：

- 置信度低于自动处理阈值；
- 车牌像素过小；
- 检测框接近图像边缘；
- 检测框面积异常大；
- 多个检测框严重重叠；
- 推理结果包含非法坐标；
- 修复或写出阶段发生错误。

阈值保存在版本化配置中。界面默认只提供“速度、均衡、精细”三个预设，高级阈值折叠显示。

### 5.4 Mask Builder

输入：检测框、用户矩形框和用户笔刷。  
输出：与原图坐标一致的二值掩码。

规则：

- 根据车牌短边按比例扩张，覆盖牌照外框；
- 靠近图像边缘时安全裁剪；
- 相邻或重叠掩码按处理窗口合并；
- LaMa 输入使用二值掩码；
- 羽化只发生在修复结果合成阶段，避免半透明掩码改变模型语义。

### 5.5 Inpainter

输入：局部 RGB 图像和二值掩码。  
输出：修复后的局部 RGB 图像。

职责：

- 围绕车牌提取包含足够车身纹理的上下文窗口；
- 按模型要求缩放和补边；
- GPU 推理；
- 把结果映射回原始局部尺寸；
- 不读取或写入源文件。

修复器使用插件式接口，为未来增加其他本地模型留出空间，但第一版只内置 LaMa。

### 5.6 Job Engine

职责：

- 管理扫描、检测、修复、复核和写出队列；
- 限制并行度，避免显存峰值；
- 每张图片错误隔离；
- 暂停、继续和取消；
- 持久保存任务清单；
- 应用重启后恢复未完成任务；
- 向界面发送不可变进度事件。

模型推理运行在线程或独立工作进程中，绝不阻塞 WebView2 界面线程。

## 6. 大图处理与质量策略

不把完整 4K/8K 成片缩小后整体修复。系统围绕每个车牌提取局部窗口，窗口包含车牌周围足够的车漆、格栅或保险杠纹理。处理完成后按原始分辨率合成回照片。

策略包括：

- 小车牌使用更高比例的上下文；
- 大车牌限制最大工作尺寸以控制显存；
- 相距较远的多个车牌分别处理；
- 相邻车牌合并窗口，避免重复覆盖；
- GPU 显存不足时降低工作块尺寸并重试一次；
- 第二次失败后进入待复核，不自动改用极慢的 CPU 并静默拖延整个批次。

自动质检只负责识别可计算的风险，不能可靠判断“肉眼无痕”。软件不得把风险规则宣传为完整审美质检。商拍交付仍需要异常复核和批次抽查。

## 7. 桌面界面

应用为单窗口、独立标签栏结构，一次只显示一个工作区：

### 7.1 批处理

- 大面积拖放区；
- 当前任务和总进度；
- 总计、已完成、待复核、处理中、失败数量；
- 暂停、继续、取消剩余任务；
- 输出目录提示；
- “进入待复核”快捷按钮。

### 7.2 待复核

- 左侧或底部缩略图队列；
- 中央大图预览；
- 检测框和掩码叠加显示；
- 矩形框、画笔和橡皮擦；
- 画笔尺寸；
- 撤销、重做、恢复自动框；
- 跳过；
- 确认并重修；
- 键盘快捷键和滚轮缩放。

### 7.3 任务历史

- 最近任务；
- 输入位置和输出位置；
- 成功、跳过、待复核和失败统计；
- 继续未完成任务；
- 打开输出目录；
- 不保存车牌文字或 OCR 数据。

### 7.4 设置

默认只展示：

- 处理预设：速度、均衡、精细；
- 自动处理开关；
- 完成后是否打开输出目录；
- 是否保留任务历史；
- GPU 设备状态。

检测阈值、掩码扩张比例、分块尺寸和并行度放入“高级设置”。

## 8. 文件与元数据安全

- 永不覆盖输入文件；
- 永不在输入目录写入临时半成品；
- 输出先写入目标目录内的唯一临时文件；
- 写出后重新打开并校验尺寸、通道和基本元数据；
- 校验成功后原子化改名；
- JPEG 尽量复用源文件量化表；无法复用时使用高质量编码；
- PNG 使用无损编码；
- TIFF 使用无损压缩；
- 复制有效 EXIF、ICC、DPI 和拍摄时间；
- 不复制已经与新像素不一致的嵌入式缩略图；
- Orientation 在像素旋转后归一化，避免输出软件重复旋转；
- 保留原文件修改时间作为可选高级设置，默认输出使用实际创建时间；
- 写出失败时删除临时文件并保留原片。

## 9. 错误处理

每张图片拥有独立状态：

```text
queued
  -> detecting
  -> auto_ready | review_required | no_plate
  -> inpainting
  -> writing
  -> completed | review_required | failed
```

处理规则：

- 损坏图片：标记失败并继续；
- 不支持格式：扫描阶段跳过并汇总；
- 模型缺失或校验失败：阻止整个任务开始，给出修复模型安装提示；
- GPU 不可用：任务开始前明确提示，不在处理中途无提示切换；
- GPU 显存不足：减小处理块重试一次；
- 单图第二次推理失败：送入待复核；
- 输出目录不可写：暂停任务并显示可操作错误；
- 磁盘空间不足：暂停，不删除已有成功结果；
- 应用崩溃：依赖持久任务清单恢复；
- 用户取消：保留已完成结果，未开始项改为已取消。

## 10. 性能与体积目标

目标硬件为 6 GB 及以上 NVIDIA 显卡。

- 典型 4K 单车牌照片：数秒级端到端处理；
- 界面拖动和缩放时保持响应；
- GPU 同时只运行一个修复任务；
- 检测可小批量执行，但不得推高显存导致修复失败；
- 正式安装包目标约 500 MB，验收上限为 600 MB；
- 首次启动不从不明社区地址下载权重；
- 发布包内权重有固定版本和 SHA-256 校验值。

性能数字必须在选定 GPU、图片尺寸和照片样本上实测后写入发布说明，不使用未经验证的“95%+”或“单图 2 秒”宣传。

## 11. 验收方案

### 11.1 实拍数据集

由用户提供至少 100 张有权用于本地测试的真实照片，只在本机保存。样本应覆盖：

- 正面和侧面；
- 近景和远景；
- 单车和多车；
- 蓝牌、绿牌和黄牌；
- 白天、夜景、逆光和强反光；
- 浅景深、运动模糊和高 ISO；
- 车牌贴近画面边缘；
- 格栅、车漆、保险杠等不同背景；
- 不含车牌的汽车内饰或局部照片。

测试清单只记录匿名样本编号和结果，不记录 OCR 文本。

### 11.2 功能验收

- 拖入文件和文件夹均可建立任务；
- 暂停、继续、取消和重启恢复有效；
- 多车牌可全部处理；
- 人工框选、画笔、橡皮擦、撤销和重做有效；
- 原片零覆盖；
- 所有成功输出可重新打开；
- 重名输出不会覆盖旧结果；
- 单图失败不会终止批次。

### 11.3 质量验收

- 在代表性实拍集合上，可见车牌自动检出率目标不低于 95%；
- 误修非车牌区域的图片比例不高于 1%；
- 人工抽检中，至少 90% 自动修复结果可直接交付；
- 所有漏检都可通过待复核工具补救；
- 无法达到指标时不得通过降低复核阈值掩盖问题，应记录失败类别并决定是否更换预训练模型或委托专业人员微调。

### 11.4 元数据验收

按格式对比输入和输出：

- 像素尺寸；
- 色彩模式；
- ICC 配置；
- DPI；
- 相机型号；
- 镜头信息；
- 曝光时间、光圈、ISO 和焦距；
- 拍摄时间；
- GPS 字段存在性。

允许变化的字段仅包括文件大小、编码相关字段、嵌入缩略图、软件名称以及已归一化的 Orientation。

## 12. 测试层次

- 单元测试：坐标映射、分块合并、掩码扩张、重名规则、状态机；
- 契约测试：Detector、Inpainter 和 Image I/O 的接口；
- 黄金图测试：固定输入、检测框、掩码和输出尺寸；
- 元数据往返测试：JPEG、PNG、TIFF；
- 故障注入：磁盘满、目录只读、模型损坏、GPU OOM、损坏图片；
- GUI 测试：拖放、标签切换、快捷键、撤销重做；
- 端到端测试：至少一个小型公开或合成测试集；
- 用户验收：真实商拍集合的盲评与失败分类。

视觉输出不采用逐像素相等断言。自动测试检查尺寸、边界、掩码覆盖和明显接缝风险，最终质量由盲评确认。

## 13. 发布与许可证

发布前生成第三方组件清单，包含：

- 组件和版本；
- 项目主页；
- 软件许可证；
- 模型权重许可证或使用条款；
- 权重来源和 SHA-256；
- 必须附带的 NOTICE 或源代码获取方式。

桌面外壳使用 pywebview 与系统 WebView2 Evergreen Runtime，不把 Qt 或浏览器内核打入安装包。安装器必须检测 WebView2；缺失时使用微软官方离线安装器。正式商业发布前仍需复核 pywebview、pythonnet 和 WebView2 的分发通知。

该规格不构成法律意见。模型代码许可证不自动证明训练数据和权重再分发权相同，因此必须分别核验。

## 14. 主要风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| PP-Vehicle 对商拍侧面和小车牌泛化不足 | 漏检 | 先做 100 张实拍基准；异常复核；必要时更换模型或委托微调 |
| LaMa 在复杂格栅上产生重复或扭曲纹理 | 结果不可交付 | 局部上下文策略；风险复核；保留可替换修复器接口 |
| EXIF Orientation 重复应用 | 输出方向错误 | 像素归一化后把 Orientation 设为正常 |
| JPEG 重编码造成画质下降 | 商拍质量降低 | 复用量化表或高质量编码；保留 ICC；视觉与文件测试 |
| CUDA、TensorRT 或驱动组合不兼容 | 无法运行 | 启动前设备自检；发布固定兼容矩阵；清晰错误提示 |
| 社区模型来源或许可不清 | 商业风险 | 第一版不下载不明 `.pt`；归档官方来源、条款和哈希 |
| 自动质检被误解为审美保证 | 劣质图片漏过 | UI 使用“风险提示”措辞；任务完成后提示抽查 |

## 15. 实施边界

该规格可作为一个实现计划的范围。实现应按以下顺序降低风险：

1. 先验证 PP-Vehicle 权重、运行时、许可证和 100 张实拍检测效果；
2. 再验证 LaMa 局部修复与输出元数据；
3. 完成无界面的批处理核心；
4. 完成任务持久化和错误恢复；
5. 接入 pywebview/WebView2 轻量批处理界面；
6. 完成待复核编辑器；
7. 做端到端验收和 Windows 打包。

如果第一阶段检测基准未达到目标，应先更换模型或调整产品预期，不继续堆叠界面功能。

- 工作流：自动处理高置信图片，异常图片进入待复核；
- 隐私：完全离线；
- 输入：JPEG、PNG、TIFF；
- 硬件：NVIDIA 6 GB 及以上；
- 手动工具：矩形框、画笔、橡皮擦、撤销和重做；
- 输出：原目录下 `车牌已消除/`，文件名追加 `_clean`；
- 模型：不要求用户训练，第一版使用官方预训练模型；
- 界面：批处理、待复核和任务历史使用独立标签栏，不同时显示。
